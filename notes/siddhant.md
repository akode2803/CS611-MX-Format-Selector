# Siddhant - notes

My part was checking that formats.py is actually correct. For that I wrote my own version of all 5 formats in verification/reference_impl.py. It's slow, it goes value by value, and I used Python fractions instead of floats so there's no rounding error in the checking code itself. Each value gets converted to its actual 6 bit code and then decoded back. Then crosscheck.py runs both versions on the same input and compares every output.

Why I trust this: my code and Akash's code are written in completely different ways, so if both give the same answer it's unlikely they made the same mistake. I find the block exponent from the bits of the number (frexp) and not from log2, since log2 can round up when the value is just below a power of 2. The Lecture 19 notebook also uses frexp for this, so that matches the class. I also made some inputs on purpose to break things: zero blocks, exact ties for RNE, values just under 2^k, values above vmax, very small values, -0, the last block of 4, the BFP exponent going outside [-8, 7], and negative block maxima where two's complement MXINT6 can use the -32 code.

What came out of it: in v1 there was a bug in the ocp exponent. For a block max like 0.12499999999999999 it gave 0.125 but the correct answer is 0.1171875. Akash fixed it. Every time formats.py changed (BFP6 16|4|5, the extra variants, MXINT6 becoming two's complement, the D13 ceil rule) I updated or reviewed my side and checked again. On the final commit all 217 cases match exactly. The D13 ceil change in my reference was added by Aryan; I went through it and it's correct (positives have to fit 31/16 of the scale, negatives 32/16), and it gives the same 4.160% for MXINT6 ceil as the report.

Reproducibility: on a fresh setup (new venv, pip install -r requirements.txt, Linux) run_all.py --fresh runs without errors, all tests pass (31 + 16 + 12 + my 16), and every table comes out the same as the committed one. The only differences are ~1e-16 float noise compared to the Mac run. Without assignment_data.npz the A-E tables can't be regenerated, and run_all now says so.

Report: I matched every decimal number in the final report (662 of them) against the regenerated results files, and all of them are there. On C, E2M3 is the best format (3.10% held-out Y error with the class rule, BFP6 second at 3.48%). The things I flagged were only text: the roll numbers placeholder, adding one line about the notebook's storage count, and calling dataset B a tie (details in verification/REPORT_CHECK_25OCT.md).

I also checked our conventions against the Lecture 19 notebook: block 32, the ocp and ceil rules, RNE, saturation, subnormals and the E3M2/E2M3 numbers all match. One thing is different: the notebook counts padding in storage, so for K=100 an MX format costs 8.00 bits/element there instead of our 6.32 (BFP6 7.00 instead of 6.28). Padding doesn't change any quantized value (zeros don't change the block max), only the storage count.

Limitation: both versions follow the same conventions table. If a convention itself is wrong (like E4M1 vmax or how we defined BFP6), both will be wrong together and my check won't catch it. MXINT6 and BFP6 aren't in the notebook, they come from the board notes. Also I did look at formats.py v0 once to see the function names, after that I only ran it.
